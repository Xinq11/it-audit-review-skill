# ITAC 复核规则

同时使用 [通用规则](common-review.md)。`R` 为本 skill 的复核建议，`M` 为项目方法论。应用控制、自动控制、IT 依赖人工控制的归类按项目口径，不把所有使用报表的工作一律当 ITAC。

| ID | 适用条件与检查动作 | 所需证据 | 输出类型 | 依据 |
|---|---|---|---|---|
| ITAC-001 | 业务控制：将具体风险/认定映射到输入、规则、处理、输出及例外；确认描述足够精确，避免“系统自动检查”代替实际逻辑 | 控制说明、业务规则、配置及流程 | documentation_issue / professional_judgment | R；M |
| ITAC-002 | 验证自动逻辑：按相关风险检查场景是否覆盖关键分支，适用时含拒绝、边界和可绕过路径；比较预期与实际结果，不要求每控制机械完成同一套场景 | 测试设计、输入、预期结果、实际输出 | evidence_gap / potential_control_exception | R；M |
| ITAC-003 | 引用环境/版本：确认测试对象与生产控制的对应依据、版本和生效期间；测试环境结果不能直接外推生产，期间变更要有影响评价 | 环境标识、部署/配置版本、变更记录 | evidence_gap / professional_judgment | R；M |
| ITAC-004 | 依赖参数/主数据：检查阈值、容差、表及主数据如何支持规则，谁可修改、期间是否变化及测试覆盖 | 参数快照、维护权限、变更、相关测试 | evidence_gap / potential_control_exception | R；S3 .B30 相关原则；M |
| ITAC-005 | 接口控制：追踪源到目标的映射、批次/记录匹配及失败、重复、重传处理；仅汇总金额相等不能自行证明记录完整 | 接口定义、日志、源目标核对、异常处理 | evidence_gap / potential_control_exception | R；M |
| ITAC-006 | 范围内 IT 依赖人工控制：分别检查所用信息可靠性与人的复核精度、调查阈值和跟进；签名不能独自证明复核执行到所需深度 | 报表、复核标准、调查和解决记录 | evidence_gap / professional_judgment | R；COM-005；M |
| ITAC-007 | 依赖 ITGC：把问题定位至受影响应用、程序/数据、权限及期间，评价其他控制和追加程序；不得把单个 ITGC 例外传播为所有 ITAC 失效 | 依赖映射、ITGC 结果、追加程序 | professional_judgment | S4 FAQ4；R；M |
| ITAC-008 | 拟沿用前期自动控制测试：核对适用准则是否允许、基准是否建立、控制未变证据、相关 ITGC 及参数依赖；条件不全时不自动沿用 | 前期测试、未变证明、当期 ITGC、重建基准依据 | evidence_gap / professional_judgment | S3 .B28—.B33；M |

对自动控制不预设“只测一个样本就够”；对 ITGC 不有效也不预设“ITAC 一定无效”。规则与证据不足时提出需要审计人员决定的追加工作，保留原结论供人工处理。
