# ITGC 复核规则

同时使用 [通用规则](common-review.md)。以下均为 `R`：待项目方法论 `M` 确认的复核实现建议，不是独立的准则强制清单。按控制实际设计选用，未在范围内的事项记录原因。时间、独立性及例外条件从 M/政策读取；无标准时不自行设阈值。

| ID | 适用条件与检查动作 | 所需证据 | 输出类型 | 依据 |
|---|---|---|---|---|
| ITGC-001 | 开通/调岗权限：按账号及人员标识匹配申请、授权、配置与生效时间；依据适用要求核对审批顺序、权限范围及调岗旧权限处置 | 申请、审批、权限记录、人员变动 | potential_control_exception / evidence_gap | R；M |
| ITGC-002 | 离职停用：匹配人员与全部相关账号，按政策时限及日历口径比较离职生效、通知和停用时间；无法匹配或缺时间只报缺口 | 离职总体、账号映射、停用日志、政策 | potential_control_exception / evidence_gap | R；M |
| ITGC-003 | 定期权限复核/特权管理：核对覆盖的用户与权限、复核人资格、实际检查内容及异常关闭；服务/共享账号按其专门规则，不默认都是违规 | 用户清单、特权清单、复核记录、变更/关闭证据 | evidence_gap / potential_control_exception | R；M |
| ITGC-004 | 普通变更：匹配需求、审批、测试、上线对象/版本及时间，核对适用的职责分离；将工单总体与实际部署来源的覆盖说明连起来 | 工单、测试、审批、部署日志、角色权限 | potential_control_exception / evidence_gap | R；M |
| ITGC-005 | 紧急变更：先确认紧急资格与专门程序，再检查适用的事后审批、测试和复核；不套用普通变更的固定时间顺序 | 紧急政策、变更及事后复核记录 | potential_control_exception / evidence_gap | R；M |
| ITGC-006 | 范围内运维：检查作业失败、告警到处置/重跑的闭环及数据影响；备份成功和恢复能力分别评价，不能相互替代 | 监控总体、失败工单、重跑核对、备份与适用恢复测试 | evidence_gap / potential_control_exception | R；M |

每项仍需 COM-003 的总体与样本检查。日期/数量差异先作为事实，解释口径、紧急流程及补偿控制后再评价；不直接据此认定缺陷等级。背景原则可查 [S4](sources.md)，具体执行标准以本项目适用资料为准。
