# 接口控制复核输出约定

默认直接输出中文 Markdown，或按用户要求保存报告。无需固定底稿模板、项目 JSON、提取清单或脚本生成的 ID；用户另需表格/JSON 时保留下列信息及可追溯位置。

## 1. 接口范围及依据

逐接口列明控制/接口编号、方向、源目标系统及环境、业务对象、匹配键与一对一/拆分/汇总关系、成功终点、期间及导出时点、时区、时限/截止规则、项目适用依据。未知项写未确认，不自行补设。

只描述本次接口控制范围。ITGC、报表/IPE、配置等仅在它们支持该接口结论时列依赖；其他领域按范围外记录，不扩展为系统总体审计。

## 2. 证据链与检查覆盖

| 链路阶段 | 本次材料及原始位置 | 该材料能支持什么 | 完成/未完成检查及原因 |
|---|---|---|---|
| 合格源总体/抽取 | 实际文件、表/页/记录标识 | 业务范围及提取条件；可靠性有无支持 | 按实际填写 |
| 发送/接收/处理 | 实际批次、消息及状态位置 | 明确成功处于哪一层，不能跳步推断 | 按实际填写 |
| 目标业务结果 | 目标明细及业务键/凭证/订单等标识 | 所测控制约定的最终结果 | 按实际填写 |
| 对账及异常闭环 | 差异、告警、修正、重传及复核 | 差异解释与最终关闭依据 | 按实际填写 |

此表按实际接口设计调整。不存在某阶段或名称不同不构成问题；没有读到某项材料，不能写成不存在。无需为填表强制索取与控制无关的资料。

引用尽量同时包含原文件、页/表/单元格或行号，以及业务/批次/消息/目标对象标识。例如 `source.csv / 第3行 / business_id=O102`、`目标明细.xlsx / 接口对账!E8`、`日志.pdf / 第2页 / request_id=...`。CSV 行号明确是否含表头；重复键用复合条件或目标独立ID区分。图片用所在页/锚点、标题及可识别对象定位，不伪造脚本图片ID。

发生计算时记录范围、筛选条件、业务键、有效状态、币种/单位、时间及匹配/转换口径，并区分已选样本与全量。可用差异表列缺失、多出、字段偏差、重复业务及超时，但不要把技术日志行数当业务笔数。

## 3. 逐条 review notes

每条意见包含：

- 接口/控制、`IFC` / `COM` 规则及具体项目依据。
- 类型：底稿记录问题（`documentation_issue`）、证据不足（`evidence_gap`）、疑似控制例外（`potential_control_exception`）、需要专业判断（`professional_judgment`）。
- 观察事实及支持/矛盾证据的精确位置，观察与推断分开。
- 对当前测试属性、成功终点、期间或底稿结论的影响；未知影响保留待评价。
- 建议补充的资料、核实及追加程序。处理优先级可按需要列出，不等于缺陷等级。

例如，明确规则要求每源订单仅形成一张有效凭证，而同一业务键已有两个独立有效凭证且未冲销，可提出疑似重复业务例外；只见两次发送或一个接收回执时，不能据此认定重复入账。

## 4. 未完成、范围外及结论支持

列明实际已读、部分读取、未读及工具未支持的文件和相关图片；说明受影响的具体程序。将资料限制、待专业判断及范围外内容分开，不把未运行可选脚本列成审计证据缺口。

最后说明原底稿结论有哪些支持、哪些矛盾或缺口尚待处理；不代替审计人员签署。无发现仅限本次已完成范围，不表示接口全年有效。源文件或规则版本中途变化时，应在稳定版本重做受影响核对。
