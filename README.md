# IT 审计底稿复核 Skill

面向支持财务报表审计的 ITGC / ITAC 底稿，沿着**风险、控制、测试、证据、例外和结论**检查记录是否完整、证据是否对应、结论是否得到支持，输出可定位的 review notes。

输入以 Excel 底稿、内嵌截图和独立附件为主。Skill 主体沉淀业务流程、复核经验、六类执行指令及按场景读取的参考规则；Agent 优先使用宿主已有的文件读取、搜索和看图工具，直接形成中文 review notes。原始底稿保持只读，附带脚本仅在需要复用解析或批量核对时选用。

## ITGC 和 ITAC 分别在审什么

| 领域 | 控制目标 | 常见核心流程 | 底稿需要说明的问题 |
|---|---|---|---|
| **ITGC：IT 一般控制** | 支撑系统、程序和数据在相关期间内可靠运行 | 访问权限管理、程序变更管理、计算机运维 | 谁可以访问或修改系统？变更如何获批、测试、上线？运行异常如何处理？ |
| **ITAC：IT 应用控制** | 在具体业务处理中防止或发现信息错误 | 输入校验、处理规则与计算、输出及接口核对、异常处理 | 数据能否完整、准确地处理？该阻止的交易是否被阻止？输出和异常是否得到核对与处理？ |

以下是常见控制流程及本 skill 的复核映射。实际选用哪些控制、执行哪些测试，由项目范围、风险及适用方法论决定。系统开发、实施和数据迁移等专项流程，需要按项目另行补充；当前没有独立专项模块。

## 检查方式怎么区分

- **Agent 按规则复核，默认路径**：使用宿主工具读取控制描述、测试程序及附件，查看图片，沿业务流程判断信息能否对应、是否存在缺口或矛盾，直接输出中文 Markdown 意见。效果依赖材料质量、宿主模型和视觉能力。
- **脚本核对，可选辅助**：需要重复解析或批量比较时，对已配置的字段和条件进行确定性比较，例如时间顺序、重复编号及金额阈值。结果是候选意见，仍要核对原始证据。
- **人工确认**：确定适用准则、方法论、政策、抽样依据及专业判断，评价最终影响并完成正式复核。

**21 条复核规则不等于 21 项自动检测。** 所有领域均由 Agent 按适用规则复核；当前可选事实脚本只支持普通变更样本表和金额阈值测试表两种映射。默认复核不要求 `manifest.json`、项目 JSON、Python 或校验脚本。

## ITGC：核心流程与逐步检查

### 1. 访问权限管理

常见流程为：**申请与授权 → 账号及权限配置 → 调岗调整 → 定期复核与特权管理 → 离职停用**。定期复核贯穿账号使用期间。

| 关键步骤 | 需要的底稿与证据 | Skill 如何检查 | 当前执行方式 |
|---|---|---|---|
| 申请、授权与开通 | 权限申请、审批、人员及账号标识、权限配置与生效记录 | 按人员和账号匹配审批与实际权限；核对授权人、权限范围及适用审批顺序，识别批准权限与实际配置不符等差异 | Agent：`ITGC-001`；授权及顺序要求由项目确认 |
| 调岗及权限调整 | 人员变动、变更申请、调整前后权限 | 检查新权限是否获授权、原岗位权限是否按政策处理；不能只看新权限开通记录 | Agent：`ITGC-001` |
| 定期复核、特权管理 | 用户及特权清单、复核范围、复核人、检查记录、异常关闭证据 | 检查对象覆盖、复核人资格、实际检查内容与异常跟进；服务及共享账号按专门规则处理 | Agent：`ITGC-003` |
| 离职停用 | 离职总体、人员到账号的映射、通知及停用时间、政策 | 匹配人员及相关账号，按政策口径检查停用时效；缺时间或映射时报告证据缺口，不推断没有停用 | Agent：`ITGC-002`；尚无离职时限自动计算脚本 |

### 2. 程序变更管理

常见流程为：**提出变更 → 适用审批 → 开发与测试 → 上线授权及部署 → 保留记录并处理例外**。具体审批节点和职责分离要求按控制设计确定；紧急变更使用专门流程。

| 关键步骤 | 需要的底稿与证据 | Skill 如何检查 | 当前执行方式 |
|---|---|---|---|
| 变更对象及总体 | 需求、工单总体、实际部署来源、期间及提取说明 | 检查对象、版本和期间是否一致，以及工单如何覆盖实际部署；工单列表本身不自动证明总体完整 | Agent：`COM-003`、`ITGC-004` |
| 变更审批 | 审批记录、批准及上线时间、普通变更政策 | 对明确为普通变更且政策要求上线前批准的样本比较时间，再核对原始审批、部署证据及授权人 | Agent：`ITGC-004`；批量时间比较可选 `FACT-001` |
| 开发及测试 | 测试内容、结果、完成时间、对象和版本、上线记录 | 比较测试完成与上线时间；检查测试是否对应实际部署变更，并支持所述测试属性 | Agent：`ITGC-004`；批量时间比较可选 `FACT-002` |
| 上线授权及部署 | 部署日志、发布版本、角色权限、执行人及授权记录 | 匹配测试、批准和上线对象，按要求检查职责分离；时间顺序正确不能单独证明授权及内容适当 | Agent：`ITGC-004` |
| 紧急变更及事后程序 | 紧急资格、专门政策、工单、事后审批及测试复核 | 先确认紧急资格与专门要求，再检查执行。没有政策时保留待确认事项，不套用普通顺序 | Agent：`ITGC-005`；选用脚本时，紧急类型跳过普通顺序比较 |

### 3. 计算机运维

常见流程包括：**作业监控 → 失败告警 → 调查处置 → 重跑及结果核对**，以及**备份执行 → 结果检查 → 按适用要求验证恢复能力**。

| 关键步骤 | 需要的底稿与证据 | Skill 如何检查 | 当前执行方式 |
|---|---|---|---|
| 作业监控、失败及重跑 | 监控记录、失败总体、告警、处理工单、重跑及核对结果 | 沿同一作业或批次追踪发现、处理和关闭；检查失败及重跑对数据完整、重复处理等影响是否被考虑 | Agent：`ITGC-006`；无专用作业日志对账脚本 |
| 备份与恢复 | 备份策略、执行结果、失败处理、适用恢复测试 | 分别复核备份执行和恢复能力的证据；备份成功不能直接支持“能够恢复”的结论 | Agent：`ITGC-006`；恢复能力及测试范围由人工确认 |

详细规则见 [ITGC 复核规则](skills/it-audit-review/references/itgc-review.md)。

## ITAC：核心流程与逐步检查

先明确业务风险与控制规则，再沿着**输入 → 处理 → 输出 → 异常处置**追踪测试和证据。参数、主数据、环境版本及相关 ITGC 是贯穿链路的依赖。

| 关键步骤 | 需要的底稿与证据 | Skill 如何检查 | 当前执行方式 |
|---|---|---|---|
| 明确风险与业务规则 | 风险及认定、控制描述、规则、阈值及例外条件 | 检查控制防什么错误，何时允许、拒绝或转人工；“系统自动检查”应能对应具体规则和测试 | Agent：`ITAC-001` |
| 输入校验 | 测试输入、字段要求、来源及校验输出 | 按设计检查相关输入风险，如遗漏、无效、重复或超范围输入；不要求所有控制机械套用同一套场景 | Agent：`ITAC-001/002`；无通用输入校验执行引擎 |
| 处理逻辑及计算 | 计算或匹配规则、测试设计、输入、预期及实际输出 | 检查关键分支与适用边界；对明确的金额阈值核对预期标签与底稿记录。其他计算、匹配、容差和舍入按实际规则复核 | Agent：`ITAC-002/004`；批量金额阈值比较可选 `FACT-006` |
| 输出及接口核对 | 接口定义、源目标记录、映射、批次日志及核对结果 | 检查字段映射、记录或批次匹配、丢失、重复和重传处理；仅汇总金额相等不能自行证明完整 | Agent：`ITAC-005`；无通用接口对账脚本 |
| 异常拦截及处置 | 拒绝结果、异常日志、调查及关闭记录、绕过或人工处理机制 | 检查应触发的异常是否触发，后续处理是否支持控制目标；识别只测正常通过、缺少关键拒绝场景的情况 | Agent：`ITAC-001/002/005` |
| 参数及主数据依赖 | 参数快照、容差或价格表、维护权限、生效及变更记录 | 核对测试规则与配置，谁能修改关键参数，期间是否变化及如何覆盖。金额脚本只使用项目明确配置的阈值 | Agent：`ITAC-004` |
| 环境、版本及期间依赖 | 生产环境对应、版本、执行日期、期间变更、ITGC 结果及依赖映射 | 检查结果对应哪个生产控制及期间；将 ITGC 问题定位到相关应用、权限、程序或数据。沿用前期自动控制测试时检查适用条件 | Agent：`ITAC-003/007/008`；最终依赖判断由人工确认 |

范围包含 **IT 依赖人工控制**时，还要分别检查信息可靠性和人的复核精度、调查及跟进，不能仅凭签名认定完成，见 `ITAC-006`。具体归类按项目口径。

审计使用的企业信息与控制执行依赖的信息（项目中可能称 IPE / IUC）按用途识别，可重叠，也可能出现在 ITGC 底稿中；不能全部归入 ITAC。详细规则见 [ITAC 复核规则](skills/it-audit-review/references/itac-review.md) 和 [通用规则 COM-005](skills/it-audit-review/references/common-review.md)。

## 两类底稿共同的审计复核流程

前面的表描述客户控制活动。复核这些活动的底稿时，还要检查审计工作是否形成完整证据链。

| 审计步骤 | Skill 的关键检查 | 规则与执行方式 |
|---|---|---|
| 1. 明确范围及风险 | 系统、环境、期间、控制、风险和方法论是否写清，测试是否对应本次目标 | Agent：`COM-001`；优先宿主工具清点，可选抽取脚本 |
| 2. 理解控制，评价设计及实施 | 控制描述、穿行及实施证据能否支持所述判断；区分制度、单时点配置和运行证据 | Agent：`COM-002`；无自动设计评价引擎 |
| 3. 总体及样本 | 总体来源、筛选、加工和完整准确性核对是否有支持；样本如何选、是否属于总体 | Agent：`COM-003/005`；可选脚本查映射表内编号重复，不自动证明总体完整或样本量充分 |
| 4. 测试及证据 | 每个测试属性是否有对应证据；样本、对象、时间、版本是否匹配；截图是否属于该样本 | Agent：`COM-006` 及领域规则；可选脚本辅助批量时间、字段、附件名称和阈值比较 |
| 5. 期间覆盖及依赖 | 期中至期末如何覆盖，期间变更如何处理，相关系统及 ITGC 依赖是否被评价 | Agent：`COM-004`、`ITAC-003/007/008` |
| 6. 例外及结论 | 异常、矛盾信息、追加程序和当前结论是否一致；区分证据不足与疑似例外 | Agent：`COM-007`；最终影响、缺陷等级和正式复核由人工确认 |

意见生成后，Agent 再核对引用位置、文件及图片覆盖情况和未完成事项。选用结构化脚本路径时，还可检查 JSON 结构、位置及源文件哈希；校验通过不证明审计判断正确。

## Skill 主体怎样组织

[SKILL.md](skills/it-audit-review/SKILL.md) 以六部分组织 Agent 的复核行为，详细业务经验留在场景参考中，按本次控制和证据选用。

| 部分 | 给 Agent 的执行指令 |
|---|---|
| 1. 适用场景 | 识别本次 ITGC / ITAC 底稿、控制及复核目标，确定应采用的场景规则 |
| 2. 输入要求 | 确认范围、期间、系统、项目依据、底稿及附件；区分已取得资料与缺失信息 |
| 3. 执行流程 | 优先用宿主工具清点、读取及看图，以控制为单位组织证据，按场景读取 references 并逐项复核；重复解析或批量比较才按需选脚本 |
| 4. 判断标准 | 区分记录问题、证据缺口、疑似例外和专业判断，核对事实及依据，不编造政策、样本量或缺陷等级 |
| 5. 输出要求 | 默认直接输出中文 Markdown review notes、原始证据定位及覆盖情况；结构化输出仅在选用时要求 |
| 6. 异常处理 | 对不可读文件、缺失附件、歧义、缺方法论及能力限制明确记录，继续可完成部分，避免把未检查写成通过 |

### 按场景选择 references

业务规则保持在现有的 `common-review.md`、`itgc-review.md`、`itac-review.md` 三份文件中，场景通过规则 ID 段区分，相关规则各保留一份并按需读取。

| 复核场景 | 应读取的参考与规则 |
|---|---|
| 所有底稿的证据链、总体样本、期间、信息可靠性及异常结论 | [通用规则](skills/it-audit-review/references/common-review.md)：`COM-001`—`COM-007` |
| 权限开通、调岗、离职及权限复核 | [ITGC 规则](skills/it-audit-review/references/itgc-review.md)：`ITGC-001`—`ITGC-003` |
| 普通及紧急程序变更 | ITGC 规则：`ITGC-004`—`ITGC-005` |
| 作业监控、失败处理、备份与恢复 | ITGC 规则：`ITGC-006` |
| 业务逻辑、输入、测试分支和边界 | [ITAC 规则](skills/it-audit-review/references/itac-review.md)：`ITAC-001`—`ITAC-002` |
| 环境版本、参数及主数据 | ITAC 规则：`ITAC-003`—`ITAC-004` |
| 输出、接口及相关异常处理 | ITAC 规则：`ITAC-005` |
| IT 依赖人工控制 | ITAC 规则：`ITAC-006`，并结合 `COM-005` |
| ITGC 依赖及沿用前期自动控制测试 | ITAC 规则：`ITAC-007`—`ITAC-008`，并结合 `COM-004` |

需要核对公开依据时再读取 [sources.md](skills/it-audit-review/references/sources.md)；输出格式见 [输出约定](skills/it-audit-review/references/output-contract.md)。只有选择脚本辅助路径时才读取 [自动事实核对](skills/it-audit-review/references/automation.md) 并准备相关配置。

### 默认执行路径

1. **清点和读材料**：使用宿主文件工具读取底稿与附件，保留文件、工作表/单元格、页码或图片对象等原始位置；列出不可读及未审阅内容。
2. **按控制组织证据**：连接风险、控制、程序、总体、样本、附件、例外和结论。图片放置位置不证明它支持附近所有样本。
3. **按场景复核**：读取相应参考段落，查看证据原图，核对测试属性、对象、时间、版本、规则及依赖；需要批量比较时再选用工具或附带脚本。
4. **直接输出并自查**：给出中文 Markdown review notes、证据定位和覆盖情况，回查意见与原始材料是否一致。默认无需生成 `manifest.json`、项目 JSON 或 `review.json`，也无需运行 Python 和校验脚本。

## 可选脚本：批量解析与事实核对

需要稳定复用的文件解析、批量表格比较或结构化下游处理时，可选用 `scripts/`。`extract_workpapers.py` 可抽取单元格、隐藏表、公式保存缓存、传统批注、合并区及内嵌图片；`check_facts.py` 在明确表头、列映射、样本起止行和政策后生成候选意见；`validate_review.py` 校验结构化结果并生成报告。选用这些工具不改变业务判断标准，也不免除查看原始证据。

### 当前六项可选事实核对

| ID | 已实现的检查 | 条件及边界 |
|---|---|---|
| `FACT-001` | 普通变更批准时间晚于上线 | 明确普通类型及上线前审批政策；紧急、未知类型不套用 |
| `FACT-002` | 普通变更测试时间晚于上线 | 明确政策；只比较记录时间，不评价测试内容或程序版本 |
| `FACT-003` | 指定标识缺失，或时间、金额及结果字段缺失/不可解析 | 限于当前映射及启用的检查路径，不是所有底稿必填项的通用校验 |
| `FACT-004` | 同一映射表内样本编号重复 | 可能是多属性测试，仍需解释；不自动判为重复抽样 |
| `FACT-005` | 明确引用的独立证据文件未能唯一匹配 | 名称匹配不等于内容已复核；内嵌截图引用另由 Agent 匹配 |
| `FACT-006` | 金额阈值与记录的预期/实际结果不一致 | 使用配置的比较符、阈值和输出标签；不连接或重演客户系统 |

日期精度不足、时区口径混用、关键字段含公式缓存、政策未配置或表头不匹配时，相关检查会跳过并说明原因。完整配置及边界见 [自动事实核对](skills/it-audit-review/references/automation.md)。

## 输出及具体例子

默认以中文 Markdown 直接给出每条 review note，包含：**控制编号或可识别的控制描述、问题类型、处理优先级、规则依据、底稿及证据位置、观察事实、对当前结论的影响、建议补充的资料或程序**。可以在聊天中回复；用户要求保存时，再写入输入目录之外的新输出位置。

| 类型 | 含义 |
|---|---|
| 底稿记录问题 | 缺少必要记录、前后不一致、引用或预期结果错误等 |
| 证据不足 | 已审阅材料不足以支持某项判断，不据此断言控制未执行 |
| 疑似控制例外 | 已见事实可能偏离适用要求，需要核实和评价影响 |
| 需要专业判断 | 适用要求、影响范围、依赖关系等需要决定 |

报告同时列出已审阅、部分审阅及未审阅的文件/相关图片，以及未完成程序和原因；证据定位使用宿主能可靠取得的原始位置，不要求脚本生成的 `file_id`。处理优先级不等于缺陷等级，未发现问题也不等于控制有效。只有用户需要 JSON，或选用结构化脚本路径时，才按 [输出约定](skills/it-audit-review/references/output-contract.md) 生成对应结构。

| 合成案例 | 对应流程 | 检查及输出 |
|---|---|---|
| 普通变更 CHG002：10:00 上线，12:00 批准 | ITGC 变更审批及上线 | 脚本发现批准晚于上线；Agent 核对截图对象及时间，再指出其与“无例外”结论不一致，列为疑似例外 |
| 规则为严格大于 1000 才阻止，AC002 输入 1000 却被阻止 | ITAC 处理规则及边界测试 | 脚本重算应为允许；Agent 核对实际输出，提出规则与结果不一致，并要求评价影响 |
| AC001、AC003 都引用“内嵌截图”，唯一图片仅对应 AC002 | 测试属性与证据匹配 | Agent 识别截图归属，列为证据不足，不用一张图片支持三个样本 |

演示输入为 [合成 Excel 底稿](skills/it-audit-review/assets/demo/input/synthetic-it-audit.xlsx)，两张截图均标注 SYNTHETIC。

- [默认宿主工具路径的中文报告](examples/native-review-notes.md)：未调用附带脚本或生成固定 JSON，通过通用读取、临时计算及图片查看完成复核。
- 可选结构化路径的 [中文报告](examples/review-notes.md) 和 [结构化输出](examples/review.json)：使用示例项目配置和清单契约。

两条路径均形成 7 条意见，并保留缺资料而未完成的检查。默认示例仅采用底稿可见的控制要求；结构化示例另使用了合成项目配置中的目标期间，因此范围说明不同。演示配置不适用于真实项目。

## 安装与使用

下载并解压 [it-audit-review.zip](it-audit-review.zip)，或复制 [skills/it-audit-review/](skills/it-audit-review/) 完整目录。

Codex 工作区安装位置为 `.agents/skills/it-audit-review/`；个人作用域可放入 `~/.agents/skills/it-audit-review/`，见 [OpenAI 官方加载说明](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills)。其他 agent 可将 [SKILL.md](skills/it-audit-review/SKILL.md) 作为入口指令，按宿主加载机制配置。

```text
使用 $it-audit-review，只读复核指定目录中的 ITGC / ITAC 底稿及附件，
优先使用现有文件和看图工具，直接输出中文 Markdown review notes、
原始证据定位、覆盖情况和未完成事项。
先确认控制范围及项目依据，不确定的政策或方法论要求列为待确认。
```

项目应提供或确认：期间、系统及控制范围、适用准则和方法论版本、政策、总体及抽样依据、底稿和附件。这些可以来自对话或项目材料，不要求先填写项目 JSON。缺资料时可先完成不依赖这些资料的检查，并明确限制。只有选用 `check_facts.py`，才需确认 [项目配置](skills/it-audit-review/assets/project.example.json) 中的表头、列映射、样本边界和政策。

### 可选脚本的本地演示与测试

默认使用所需能力取决于宿主的文件与视觉工具，不以 Python 为前提。宿主能可靠读取 Word、旧版 `.xls` 或其他格式时，可按同一业务规则复核，并保留原始定位及读取限制。

以下仅是附带脚本路径的依赖：Python 3.10+；Excel、图片、UTF-8 文本及 CSV 抽取使用标准库，PDF 文本抽取可选 `pypdf`。附带解析器不支持 Word 和旧版 `.xls`，不自动安装包或进行 OCR；扫描页及图片内容仍需宿主的视觉或可用 OCR 能力。

在仓库根目录运行，输出位置需尚未使用：

```bash
python3 skills/it-audit-review/scripts/extract_workpapers.py skills/it-audit-review/assets/demo/input --output-dir work/demo/extracted
python3 skills/it-audit-review/scripts/check_facts.py work/demo/extracted/manifest.json --config skills/it-audit-review/assets/project.example.json --out work/demo/facts.json
```

这两条命令仅完成抽取及事实候选核对。只有继续采用结构化路径时，Agent 才需按流程查看证据并按约定形成 `review.json`，再执行：

```bash
python3 skills/it-audit-review/scripts/validate_review.py work/demo/extracted/manifest.json work/demo/review.json --report work/demo/review-notes.md
```

回归测试针对附带脚本运行，不是使用 skill 的前置步骤：

```bash
python3 -m unittest discover -s skills/it-audit-review/tests
```

- 附带脚本已通过 30 项回归测试；独立 Agent 分别完成了结构化及默认宿主工具路径的合成复核，默认路径未调用附带脚本。验证不代表真实客户底稿上的识别准确率，也不证明所有宿主工具都能同样读取材料。
- 不修改原始底稿，不执行宏或外链。附带脚本不计算 Excel 公式，公式缓存、未解析绘图及外部链接等限制会在其清单中说明；默认路径也需记录宿主读取和视觉识别的实际限制。

- 通用规则不代表特定机构的方法论。样本量、政策时限、缺陷等级和正式签署按项目要求及专业判断处理；客户材料在获准环境和授权范围内处理。
