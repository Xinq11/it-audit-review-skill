# ITAC 接口控制底稿复核 Skill

当前版本**仅针对 ITAC 下的接口控制**，沿着源业务数据、抽取/发送、接收/处理、目标业务结果和异常闭环，复核底稿中的程序、证据及结论是否对应。

保留现有仓库及调用名 `$it-audit-review`，当前能力以本接口专用范围为准。默认使用 Agent 已有的文件、视觉及计算工具，按业务场景读取参考规则，直接输出中文 review notes；Python 文件提取为可选辅助。

## 复核对象与范围

适用于系统间批次/文件传输、API、消息/事件或数据同步等接口的审计底稿。每次以**某接口、某方向、某控制、某期间的一组底稿与证据**为复核单位。

需要先明确接口约定的完成终点：发送成功、目标接收、业务处理完成或入账并非同一层次。某接口只要求到达接收端时，不强制取得入账证据；控制要求形成目标业务结果时，也不能只用 HTTP 200 或队列接收回执支持结论。

本版本复核已提供的底稿与证据，不自动运行客户接口或开展接口功能、性能、安全测试。权限、变更、运维及其他 ITAC 内容不作为独立业务范围；相关 ITGC、IPE/IUC、参数或版本仅在它们支持本接口结论时作为依赖考虑。

## 接口控制的核心流程：每一步查什么

**合格源总体 → 抽取与发送 → 接收及处理 → 目标业务结果 → 源目标核对 → 异常修正/重传 → 复核关闭及结论。**

该链路按实际架构调整，并非每个接口都必须存在同名系统或独立步骤。

| 关键步骤 | 主要底稿与证据 | Skill 的检查动作 | 常见问题及判断边界 |
|---|---|---|---|
| 1. 明确接口及成功终点 | 接口/数据流说明、控制描述、方向、系统环境、状态字典、责任分工 | 将风险与控制目标对应到实际链路，明确“成功”在哪一层；按批次、消息及业务对象串联证据 | 批次显示成功但部分业务拒绝；不把中间确认等同于最终业务完成，也不要求所有接口验证到入账 |
| 2. 确认总体及样本 | 总体查询/筛选、提取时间、状态、加工过程、选样依据 | 区分批次、消息、业务单据及行项目；检查失败、重试及相关状态是否被测试目标覆盖 | 只用成功清单支持全部运行结论；样本量及可外推范围按项目方法论确定 |
| 3. 核对源目标完整性 | 两端明细、业务键/行键、关联表、拆分/汇总及排除规则 | 双向追踪业务对象，解释缺失、多出、拆分、归集及过滤；明确核对范围是样本还是全量 | 不强制一条消息对应一条目标记录；合法一对多或多对一须按批准的转换关系核对 |
| 4. 核对准确性及汇总 | 字段映射、版本、转换规则、原值、币种/单位、明细及汇总 | 核对关键字段、金额、符号、日期、科目等实际所需属性，重算适用转换；让汇总回到明细 | 两边总笔数、总金额相等，仍可能漏一笔又重复一笔；不能只看净额，也不自行设容差 |
| 5. 核对及时性与截止 | 业务日期、事件及目标完成时间、时区、SLA、观察时点 | 按实际时限及业务日期口径比较，解释在途、跨午夜、期后到达和未完成项 | 最终成功不抹去原延迟或跨期；正常在途不直接判为丢失，未知时限不自行判超时 |
| 6. 核对重复及重传结果 | 重试/去重记录、业务唯一性规则、目标独立对象、冲销或更新关系 | 区分重复传输与重复业务效果；沿原异常关联重传，回到目标结果再核对 | 多次请求可能只形成一个有效结果；同一业务形成多个不应有的有效结果才是待评价的重复影响 |
| 7. 核对异常与关闭结论 | 异常清单、告警/工单、原因、修正授权、补数/补偿、再对账及复核 | 追踪发现、责任人、调查、纠正、最终结果和关闭；检查未解决项及相关依赖如何进入底稿结论 | 工单关闭不代表差异消除；重试成功不代表原失败及时关闭；不能只保留支持“无例外”的材料 |

[SKILL.md](skills/it-audit-review/SKILL.md) 组织执行方法，详细经验保存在按场景读取的 references 中。

| 部分 | 本版本的具体内容 |
|---|---|
| 适用场景 | 只识别并复核 ITAC 接口控制；相关依赖与范围外内容分开 |
| 输入要求 | 接口定义、业务键、状态终点、期间及政策，底稿、源目标和异常等现有证据；不强制固定模板 |
| 执行流程 | 定义及总体 → 源目标勾稽 → 字段/时间/重复 → 异常重传 → 底稿结论及证据回查 |
| 判断标准 | 每条经验明确适用条件、所需证据、核对动作、例外和影响；政策、时限和映射以实际项目为准 |
| 输出要求 | 中文 review notes、链路证据及覆盖表、差异事实、未完成和范围外事项，定位到原始记录 |
| 异常处理 | 缺口径、不可读、在途跨期、合法拆分/冲销、矛盾及依赖不足时如何继续并保留判断 |

## 默认执行方式

1. 使用宿主工具清点、读取底稿与附件，保留原始文件和记录位置，说明工具读取限制。
2. 确认接口边界、源目标和目标完成状态；读取通用及接口定义规则。
3. 根据当前控制目标，用业务键关联源与目标，核对实际适用的字段、汇总、时间及重复影响。
4. 对异常、重试或工单沿链路追踪，核对修正授权、最终业务结果、再对账和关闭证据。
5. 回到原底稿，核对编制人声称执行的程序、证据和结论是否一致；明确没有执行或无法完成的复核。
6. 直接形成中文 Markdown，逐条核实引用、事实、依据和影响。用户另需表格或 JSON 时保留相同信息，不强制脚本 schema。

需要计算时可以使用宿主工具或临时代码。计算前明确业务键、一对一/拆分/汇总关系、有效状态、币种/单位、筛选条件、时间及转换规则；不能把某案例的固定逻辑当成所有接口规则。

## 输出示意

报告先列接口范围及链路证据覆盖，再给出逐条意见。每条意见包括：**接口/控制、规则及项目依据、问题类型、事实与原始位置、对当前结论的影响、建议核实和补充程序**。

| 类型 | 适用表达 |
|---|---|
| 底稿记录问题 | 执行记录、引用、汇总或结论存在矛盾等 |
| 证据不足 | 当前材料不能支持某项判断；不据此声称客户控制未执行 |
| 疑似控制例外 | 已有事实可能偏离明确适用要求，需核实并评价影响 |
| 需要专业判断 | 规则适用、正常在途/转换解释、依赖及最终影响需要决定 |

处理优先级不等于缺陷等级，未发现问题不等于接口全年有效；底稿复核及自行重算也不能补写成编制人曾经执行过的程序。完整格式见 [输出约定](skills/it-audit-review/references/output-contract.md)。

## 安装及调用

下载并解压 [it-audit-review.zip](it-audit-review.zip)，或将 [skills/it-audit-review/](skills/it-audit-review/) 完整目录复制到工作区 `.agents/skills/it-audit-review/`；个人作用域可使用 `~/.agents/skills/it-audit-review/`。加载机制见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills)。其他 agent 可按其宿主机制读取入口指令。

```text
使用 $it-audit-review，只读复核指定的 ITAC 接口控制底稿及附件。
先确认接口范围、源目标、业务键、完成状态及期间，
沿完整准确性、时间与截止、重复、异常重传和关闭逐步检查，
输出中文 review notes、原始证据位置和未完成事项。
相关 ITGC 或报表资料只作为接口依赖考虑。
```

默认路径依赖宿主的文件与视觉能力，不以 Python、项目 JSON 或固定模板为前提。资料不足时先完成独立可做的工作，并说明限制；不自动上传外部服务、访问客户系统或安装包。

### 可选文件提取

当前仅附带 `extract_workpapers.py`，用于需要复用的 Excel/图片/文本提取；没有预置接口自动对账引擎。以前的普通变更/金额阈值核对及固定结果校验器不属于接口专用版本。

在仓库根目录执行，输出目录需位于输入之外且尚未使用：

```bash
python3 skills/it-audit-review/scripts/extract_workpapers.py /absolute/input --output-dir work/extracted
```

脚本路径需要 Python 3.10+；Excel、图片和文本使用标准库，PDF 文本抽取可选现有环境中的 `pypdf`。不执行宏、公式或外链，不自动 OCR；附带解析器不支持 Word 与旧版 `.xls`，宿主可另行使用可靠工具读取。

文件提取回归测试：

```bash
python3 -m unittest discover -s skills/it-audit-review/tests
```

## 验证与项目边界

- 接口业务复核以宿主工具读取及场景规则判断为主。独立 Agent 已按当前规则全量复核合成案例的 5 笔源订单、5 张目标凭证、15 条事件及 1 条工单，识别对象级差异并保留总体可靠性证据限制，未把 O101 的正常重试误判为重复业务。
- 可选提取工具的 7 项回归测试及 skill 结构校验通过。该验证不代表真实客户底稿上的问题识别准确率。
- 文件名、成功标记、图片锚点或哈希不能单独证明交换完整、业务成功或证据真实。
- SLA、容差、样本量、业务唯一性、合法转换及缺陷等级按项目依据和审计人员判断确定，不由模型自行设定。
- 本 skill 是通用复核方法，不代表特定机构方法论。公开资料仅作原则背景，最终适用要求、审计判断和正式签署由项目人员确认。
